# Agent instructions

This repository is a long-term memory for a personal AI agent. Owner or guest, read `memory/START.md` first and follow its rules. `sources/` is read-only. Routine memory writes stay under `memory/`; setup may also change `brain.toml` and generate `.context.md`.

## If this brain is not set up yet

You will know because `memory/agent/SOUL.md` still has bracketed placeholders and `memory/agent/Tasks.md` has only T-001. Set it up with the owner present. Follow these steps in order and say what you are doing. The runtime is the Demiurge harness; its wiring is in `memory/Runtime/README.md`.

1. **Ask in a conversation, not a form:** what they want to call you; their name; their timezone and roughly when they wake and sleep; their Demiurge Home and any rooms they want you in; what they want you for, in their words; and two or three things about how they like to be spoken to. Keep specific answers verbatim. Ask for permanent owner ids; never guess them.
2. **Write what you learned:** fill SOUL and `memory/human/Profile.md`; write `memory/Conversations/<today> First conversation.md` quoting their answers; set the Home row and Destinations in `memory/agent/Channels.md`. Leave unknown facts as unknown.
3. **Set identity and environment:** fill `human_name`, `agent_name`, `owner_user_ids` and the owner's IANA `timezone` in `brain.toml`. Keep `runtime_dir = "Runtime"`. Give the repo its own local git name and email for night commits. Arrange unattended authentication with the owner; do not test it by pushing without permission.
4. **Configure the harness:** create or check `~/.harness/agents/<id>.json` against the Runtime example. Confirm `workspace`, `vault`, model `credential`, `model`, `env.AGENT_HOME`, `env.VAULT_REPO`, `env.PATH`, and `demiurge.url` and `demiurge.credential`. Paths are absolute; the workspace owns `records/`, `scripts/` and `harness/`, and the vault repo is the working directory. The owner signs in with `harness login --credential <model-credential>` and supplies the Demiurge agent key on stdin to `harness set-key <agent-credential>`. Config holds credential names, never key values.
5. **Install and generate:** if needed, install agent-brain 0.30+ with `python3 -m pip install git+https://github.com/demiurge-lab/agent-brain`. From the repo, with `AGENT_HOME` and `VAULT_REPO` set, run `brain install-scripts`, `brain install-skills`, `brain nightly --write`, then `brain compile-context --write`. Scripts live in `$AGENT_HOME/scripts/`, core skills in `memory/Runtime/skills/`, session context in `.context.md`; `brain paths soul` gives the canonical identity file.
6. **Declare routines:** run `brain schedule init` to write the standard routines for this edition into `memory/Runtime/schedule.toml`. Use `brain schedule set <name> --cron "<five fields>" --skills <skill> --prompt "<instruction>" --deliver <destination>` to create or adjust one; use `--script <script> --no-agent` for a script-only routine and `--monitor <script>` for a gate. Keep `watch-signal.sh` on the watch routine. Use the owner's local hours (`brain timezone`); people runs before morning and prime half an hour before it. Use `local` for night/internal output and `demiurge` for Home. Read back `brain schedule list` and run `brain schedule check`. Never edit `$AGENT_HOME/harness/jobs.json`.
7. **Start and verify:** have whoever runs the host start launchd service `ai.demiurge.harness.<id>`, running `harness serve <id>`. Check `~/.harness/logs/<id>.log` for `serving Demiurge`, routine runs and errors. The harness must implement the current runtime contract: it reads `.context.md` and applies schedule changes within a minute. Confirm routines and next runs in Demiurge, run `brain validate`, and check identity and generated context in a fresh conversation. Report any deployment gap; do not improvise an installer.
8. **Hand off:** tell the owner the five night stages and their local times, and what to check in the morning: night commits, digest and briefing. Leave setup changes for review. Commit, push or publish only when explicitly asked.

Ask before handling credentials or sending messages. Never read stored credentials or put a key in a note, config or command history.

## Once it is set up

Use `brain-recall` for retrieval and small daytime writes. The night routines own structure. Never edit `sources/`, SOUL, the skills or the Memory Spec from a routine; those change only when the owner asks, or when a pending engine migration says so.

Change routines only through `brain schedule list | set | pause | resume | remove | check`, after recording the request. The owner can change anything. The briefing hour and routines the owner asked for by name stay with the owner. A skill's own additions belong under `## Local`; the 09:00 upgrade preserves them.
